论文名称：Learning Transferable Visual Models From Natural Language Supervision

阅读日期：2026.10.22

所属方向与编号：通用基础论文-03

预知识：

  1. L1：管比例、频次、稀疏，适合统计特征；

  2. L2：管方向、相似度、检索，所有Embedding通用；

  3. L2归一后点积等价余弦相似度，是工业界向量检索的核心基石；

  4. 永远区分：归一化是预处理，正则化是损失惩罚。

  • 零样本 (Zero-shot) 模型没见过某个任务/数据集的任何训练样本，直接就能做。像一个人没学过法语单词，但靠语言能力猜出意思
  • 少样本 (Few-shot, k-shot) 只给模型每个类别 k 个例子（如 4-shot = 每类 4 张图）
  • 嵌入 (Embedding) 把图像或文字变成一串数字（向量）。语义相近的东西，向量在空间中距离也近。”猫”和”狗”的向量近，和”飞机”的远
  • 对比学习 (Contrastive Learning) 让”该配对的东西”向量靠近，”不该配对的”向量远离。就像教孩子认图卡：图和正确的词放一起，错误的词排除掉
  • 线性探针 (Linear Probe) 冻结预训练模型，只在其输出的特征上训练一个简单的逻辑回归分类器。用来检验特征本身的质量——如果简单分类器都能用好，说明特征很棒
  • 分布偏移 (Distribution Shift) 测试数据的来源和训练数据不一样。比如模型在杂志照片上训练，考试却用手机随手拍的照片
  • prompt / 提示工程 通过精心设计输入文字的”措辞模板”来提升模型表现。如把类别名”狗”包装成”一张狗的照片”再输入
  • batch 一次训练同时处理的样本组。CLIP 用了超大的 32,768
  1. 这篇论文要解决什么问题？

  解决计算机视觉模型“不通用、不可扩展”的问题——让视觉模型像 GPT 一样，直接从互联网海量图文数据中学习，从而不需要人工标注、不需要重新训练，就能零样本完成任意视觉任务。

  1. 这篇论文干了什么？

    1. 造了一个大规模数据集（WIT，WebImageText）

      • 从互联网收集 4 亿（图像，文本）对

      • 用 50 万个查询词搜索，每个查询最多保留 2 万对，尽量覆盖所有视觉概念

    2. 设计并训练了 CLIP 模型

      • 方法极简：给定一批 N 对图文，预测哪张图配哪段文字，而不是生成文字的具体内容

      • 效率发现：这个“配对”任务比“预测文字内容”的任务在零样本迁移效率上高约 12 倍

      • 架构：图像编码器（改进 ResNet 或 ViT）+ 文本编码器（Transformer），共享一个多模态嵌入空间

    3. 做了大规模实验验证 (核心！！！！！！！！！)

    注：

      对于本篇论文，大篇幅的使用实验，验证了使用所提到的 CLIP 的架构，去训练出的参数是可以应用到任何视觉任务的 ，这个证明本身就是本篇论文的最大的贡献。

      也就是说，clip经过训练后的模型参数，在推理时，输入图片和文字描述，会生成相应的向量，然后根据相似度进行图文匹配

    CLIP 训练好之后，怎么准备数据、怎么使用?

    1. 快速给图片打类别标签，类别可以随时改
      • a. 准备图片
      • b. 写类别名（这就是全部的”数据准备”）
      • 套提示模板（加提示能提升精度，论文证明的）
      • 推理+预测结果
    2. 图片检索、内容审核、素材管理
      • 准备自己的图库
      • 首先每个图片 encode_image() 存成向量库
      • 输入一句话，直接返回相关的图片

    其他先关的用法…….. 。

  1. 输入和输出分别是什么？

  本文对于模型的设计描述比较少，但是原文中提到“Enabled by the large amounts of publicly available data of this form on the internet, we create a new dataset of 400 million (image, text) pairs and demonstrate that a simplified version of ConVIRT trained from scratch, which we call CLIP, for Contrastive Language-Image Pre-training, is an efficient method of learning from natural language supervision.”， 也就是后面这篇文献中的ConVIRT模型的简化版本 Contrastive Learning of Medical Visual Representations from Paired Images and Text

基于ConVIRT，CLIP主要做出了以下简化：

  • ConVIRT中的 image encoder 的参数是 ImageNet 初始化的，而 CLIP 直接用 random 初始化；
  • ConVIRT的 projection head 是 non-linear 的，而 CLIP 采用 linear 的 projection；
  • CLIP去掉了 ConVIRT 中 text transformatio（指均匀从text中采样句子），因为 CLIP 数据集中有很多只出现过一次的（image，text）；
  • CLIP的 image transformation 只用了 resize 和 squared crop；
  • CLIP loss中的 temperature 参数τ是可学的。

训练阶段：

输入是一个 batch 的图文对：

$$
{(I_i, T_i)}_{i=1}^N
$$

其中：

  • $I_i$：一张图像；
  • $T_i$：与这张图配对的一段文本，通常是标题、说明、alt-text 等；
  • $N$：batch size，论文里很大，达到 32,768。

模型内部输出：

  • 图像特征：$I_f = \text{ImageEncoder}(I)$
  • 文本特征：$T_f = \text{TextEncoder}(T)$

再经过线性投影和 L2 归一化，得到多模态嵌入：

$$
I_e = \text{L2Norm}(I_f W_i), \quad T_e = \text{L2Norm}(T_f W_t)
$$

然后输出一个相似度矩阵：

$$
\text{logits}_{ij} = \tau \cdot (I_{e,i} \cdot T_{e,j})
$$

也就是 batch 内每张图和每段文本的余弦相似度，乘以可学习温度 $\tau$。

训练目标是让对角线上的真匹配对相似度高，非对角线上的错配相似度低，用对称交叉熵损失。

推理 / 零样本分类阶段

输入是：

  • 一张待分类图像 $I$；
  • 一组候选类别文本，比如 ImageNet 的 1000 个类名，通常会套上提示模板：

$$
\text{“a photo of a {label}.”}
$$

输出是：

  • 图像和每个类别文本的相似度；
  • 经过 softmax 后得到类别概率分布；
  • 取概率最高的类别作为预测结果。

本质上，CLIP 的文本编码器在测试时临时“生成”了一个零样本线性分类器。

论文名称：Segment Anything

阅读日期：2026.10.25

所属方向与编号：通用基础论文-04

预知识

  1. MAE（Masked Autoencoder）

  一种自监督预训练方法：把图像随机遮住一大块，让模型根据没遮住的部分重建被遮部分。学完后拿来初始化 ViT，比从零训练效果好。SAM 的 image encoder 就用 MAE 预训练的 ViT-H 初始化。

  1. Positional Encoding（位置编码）

  Transformer 本身不知道“位置”，所以要给每个 token 加上表示位置的向量（论文用的是文献 [95] 的傅里叶特征式编码）。SAM 里点的位置、框的角点都用它编码。

  1. Transformer Decoder / Self-Attention / Cross-Attention
  • Self-attention（自注意力）：一串 token 互相“看”，交换信息。
  • Cross-attention（交叉注意力）：两组 token 之间交换信息。SAM 的 mask decoder 里是双向的：prompt→图像、图像→prompt。
  • 轻量 mask decoder：2 层 Transformer decoder，每层 4 步（自注意力 → token 看图像 → MLP → 图像看 token），最后 output token 变成“动态线性分类器”逐点算出 mask。
  1. NMS（Non-Maximum Suppression，非极大值抑制）

  去掉重复检测的经典后处理：一堆重叠的候选里只留分数最高的。

  1. Mask（掩码）
      一张和原图同尺寸的 0/1 图，标记哪些像素属于目标物体。

  2. IoU 预测（IoU prediction）

  模型给每个输出的 mask 预测一个置信分数（估计的 IoU），用于：多 mask 排序、NMS 排序、选择下一轮迭代的 mask。训练用 MSE 对齐“预测 IoU”与真实 IoU。

  1. IoU / mIoU（交并比 / 平均交并比）

  IoU 两个 mask 的交集面积 ÷ 并集面积，0~1，分割最核心指标。mIoU 是对很多物体/数据集求平均。论文里几乎所有分割结果都用它。

  1. SA-1B（Segment Anything 1B）

  本文发布的数据集：11M 授权且保护隐私的图像 + 1.1B 高质量 mask。图像平均 3300×4950（发布版短边缩到 1500px），人脸和车牌已模糊。只包含全自动阶段生成的 mask（99.1% 的 mask 本来就是全自动的；消融显示只用自动数据只掉 ~0.5 mIoU）。比最大的已有分割数据集 Open Images 多 11× 图像、400× mask。

  1. embedding

  在自然语言处理 (NLP) 任务中，处理文本需要将每个单词转换成对应的数字表示。大多数Embedding方法都归结为将单词或标记转换为向量。各种嵌入技术之间的区别在于它们如何处理这种“单词→向量”的转换。

  Embedding不仅适用于文本，还可以应用于图像、音频甚至图数据。广义上讲，Embedding是将（任何类型的）数据转换为向量的过程。

  1. 本文主要解决了什么问题？

  给“图像分割”这个领域也造一个像 GPT 那样的基础模型。本文解决了三个相互关联的问题：

  1. 什么任务可以支持零样本泛华？

  提出 promptable segmentation （可提示分割）：给定任意的 prompt ，返回有效的分割 mask ，即使 prompt 有歧义，也要返回至少其中一个对象的合理 mask。

  1. 什么样的架构？

  首先需要灵活支持多种 prompt ，其次，要实时出 mask ，

  1. 什么数据可以支持？

  互联网上的 mask 极少，本文自构建了“数据引擎”。最终的数据集称为 SA - 1B

  1. 输入和输出是什么？

输入：

① 图像：

  1. 尺寸处理
    • 原图先被 resize + padding 到 1024 × 1024（短边拉到 1024，长边方向补灰边）；
    • 不是裁剪，而是缩放，保证物体不丢。
  2. 经过 image encoder 后
    • ViT-H 把 1024×1024 切成 64×64 个 16×16 的 patch；
    • 输出 image embedding：64 × 64 × 256（记作 C×H×W = 256×64×64）；
    • 即图像被压缩成“16 倍下采样的特征地图”，每个空间位置是一个 256 维向量。

注意：embedding 在 prompt 之前计算

② Prompt

  论文把 prompt 分为稀疏（sparse）和稠密（dense）两类。区分标准：有没有空间上的连续结构。

  • 稀疏 = 指明“在哪、是什么类型”的少量 token（点/框/文本）→ 变成几个 256 维向量；
  • 稠密 = 与图像同空间结构的提示 → 变成一张与图像 embedding 相加的特征图。

prompt 分为以下四类：

  1. 稀疏 prompt：点

    原始形式：图像上的一个坐标 + 一个标签（前景点还是背景点）。

    编码成什么：一个 256 维向量，由两部分相加而成：点的 embedding = 位置编码(坐标) + 类型 embedding(前景 or 背景)

  2. 稀疏 prompt：框

    原始形式：一个 bounding box（左上角 + 右下角两个坐标）。

    编码成什么：两个 256 维向量（一对 token）：左上角 token = 位置编码(左上坐标) + "左上角"类型 embedding    和   右下角 token = 位置编码(右下坐标) + "右下角"类型 embedding

    为什么是两个 token 而不是拼接成一条向量？

      因为四个角的信息本质上是两组独立的位置，拆成一对 token 让 decoder 的注意力机制能分别“看到”两个角。

  3. 稀疏 prompt：文本

    原始形式：任意文字，如 “a wheel”、”beaver tooth grille”。

    编码成什么：丢进 CLIP 的 text encoder（ViT-L/14@336px，论文里最大的公开 CLIP），取输出向量，做 L2 归一化后作为 256 维（对齐后）的 prompt embedding。

    CLIP 是冻结的，SAM 不训练它；

  4. 稠密 prompt：mask

    原始形式： 一个粗略的 mask（比如上一轮交互的预测结果）。

    编码成什么： 一个与图像 embedding 同尺寸的 64×64×256 张量，处理流程：

      每层之间夹 GELU 激活和 LayerNorm。

      如果没有提供 mask prompt，不是什么都不加，而是给每个图像 embedding 位置加一个学出来的 “no mask” embedding——让模型明确知道“当前没有 mask 提示”，而不是把“缺失”误解成“全零 mask”。

输出：

Ambiguity is much rarer with multiple prompts and the three output masks will usually become similar. To minimize computation of degenerate losses at training and ensure the single unambiguous mask receives a regular gradient signal, we only predict a single mask when more than one prompt is given. This is accomplished by adding a fourth output token for an additional mask prediction. This fourth mask is never returned for a single prompt and is the only mask returned for multiple prompts.

关于多个 prompt 原文描述：

  • 第 4 个 output token 是额外加的、专门处理多 prompt 情况；
  • 单 prompt 时它永不返回；多 prompt 时它独占返回（因为此时歧义已被多重提示消除，3 个输出会趋同，再输出 3 个会造成退化 loss）。

By default we predict three masks, since we observe that three layers (whole, part, and subpart) are often enough to describe nested masks. During training, we compute the loss (described shortly) between the ground truth and each of the predicted masks, but only backpropagate from the lowest loss.

关于单个 prompt 原文描述：

  • 3 个输出对应 3 个嵌套层级：整体物体 / 部分 / 子部分（如”人 / 衬衫 / 口袋”）；
  • 训练时对 3 个输出都算 loss，但 只回传最小的那个

① mask

  模型不是用固定的卷积头出 mask，而是“根据当前 prompt 现场算出一个分类器”（那个 256 维向量 v 就是分类器的权重）。不同 prompt → 不同 v → 不同 mask。

② IoU 置信分数

  每个 mask 同时输出一个标量分数 = 模型预测的“这个 mask 与真实物体边界的 IoU”。

  1. 整体流程是什么？各模块分别做什么？

① Image encoder（重）

  • MAE 预训练的 ViT-H/16（windowed attention + 4 个全局注意力块）
  • 每张图只跑一次，可先于 prompt 计算；输出 16× 下采样的 embedding

② Prompt encoder（轻）

  • 点 = 位置编码 + 前/背景可学习 embedding
  • 框 = 左上/右下两个角的 embedding 对
  • 文本 = CLIP text encoder
  • mask = 卷积嵌入后与图像 embedding 逐元素相加；无 mask 时加“no mask”可学习 embedding

③ Mask decoder（轻，~50ms 在浏览器 CPU 上）

  • 2 层 Transformer decoder，每层 4 步：[ token 自注意力 ] → token→ [ image 交叉注意力 ] → [ pointwise MLP ] → image → [ token 交叉注意力 ]（双向更新）
  • 上采样 4× 后，output token 经 MLP 变成动态线性分类器，与上采样 embedding 做逐点内积得 mask
  • 同时预测 IoU 分数用于排序

  效率逻辑：重的一步（image encoder）每图一次；轻的一步（prompt encoder + decoder）每次 prompt 只需 ~50ms，所以图像 embedding 的开销被不同 prompt 摊销，重轻是计算量（计算开销）的大小。

  1. 与前一篇相比，核心变化是什么？

      相对于前一篇的 CLIP 模型的的论文，本篇侧重于对图片内部的物品的分类标注，而 CLIP 则是对图像的一个标签分类（识别图片中的物品是什么东西，并给出命名，反之依然）。

      虽然偏重不同，但是本文的部分细节仍需要 CLIP 模型的内容，正如前面提到的当输入的 prompt 为文本时，采用的是 CLIP 的文本编码器。

      当去标注的时候，可能也会使用 CLIP 去将文本和图片进行关联。目前所有变式基于第一篇 transform 不断的从文本，到图片（ViT），再到文本与图片两者的结合（CLIP），到本篇进行图片里面的相关分析。
