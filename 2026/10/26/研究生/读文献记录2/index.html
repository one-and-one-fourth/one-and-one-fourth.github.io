读文献3-BLIP-2 / LLaVA

本文最后更新于 2026年10月30日 下午

论文名称：BLIP-2: Bootstrapping Language-Image Pre-training with Frozen Image Encoders and Large Language Models

阅读日期：2026.10.26

所属方向与编号：通用基础论文-05

预知识

  1. 微调 (Fine-tuning) :在预训练基础上，用小数据把模型”调教”到某个具体任务。类比：入职培训
  2. 涌现能力 (Emerging Capabilities) : 模型大到一定程度后没人教也会的本领，比如 BLIP-2 看图写诗、编对话
  3. OPT / FlanT5 : Meta 的开源 LLM（OPT）/ Google 经指令微调的 LLM（FlanT5）。两种类型的”语言高手”，都被冻结
  4. Decoder-only vs Encoder-Decoder ： LLM 的两种结构：前者只会”接龙式生成”（GPT 类），后者”先理解再生成”（T5 类）
  5. 信息瓶颈 （Information Bottleneck）： 257 个图像 token 被压缩成 32 个 query 输出——把一大锅汤熬成浓缩汤，只留有用的信息
  6. 注意力掩码 (Attention Mask) : 控制谁能看见谁的”遮挡板”。论文用三种：单模态掩码（query 和 text 互相看不见）、双向掩码（全可见）、多模态因果掩码（text 能看 query 但只能看自己前面）
  7. LLM （Large Language Model），大型语言模型，在海量文本上预训练的生成式语言模型，具备强大的语言生成与零样本迁移能力。
  8. 软视觉提示（软视觉token）：Q-Former 的 32 个输出向量经全连接层投影到 LLM 词嵌入维度后，前置拼接在输入文本嵌入之前，作为 LLM 的“视觉条件输入”。LLM 将其当作可理解的特殊“提示”来生成与图片相关的文本。
  1. ITC (Image-Text Contrastive Learning 图文对比学习) : 给一对匹配的图文打高分，给不匹配的打低分。让模型学会”图和文是否讲同一件事”
  2. ITM ( Image-Text Matching 图文匹配) : 二分类题：这张图和这句话配吗？答对/答错。更精细的对齐
  3. ITG (Image-Grounded Text Generation 图像引导文本生成) : 看图补文：给定图片和文字的前半部分，生成后半部分。逼着 query 把”写这句话需要的视觉信息”全部抓出来
  4. LM Loss (Language Modeling Loss 语言建模损失) : 标准”文字接龙”训练：预测下一个词
  5. Prefix LM Loss ( 前缀语言建模损失) : 把文本切成”前缀+后缀”，前缀和视觉信息给编码器，后缀让解码器生成。用于 FlanT5 这类结构
  6. CapFilt (Captioning + Filtering) : 用一个强模型给网络图片生成字幕并过滤，提升训练数据质量。

ITC / ITM / TIG 都是预训练目标

1. 这篇论文要解决什么问题？

  如何在不训练（冻结）现成视觉模型和 LLM 的前提下，以极低的训练成本设计一个高效的桥接模块，弥合两者之间的模态鸿沟，让视觉信息被 LLM 真正理解，从而既避免代价高昂的端到端训练、又保住单模态模型的既有能力，最终打通视觉与语言。

背景：

  当前视觉-语言预训练（VLP）领域的结构性矛盾：近年来，视觉侧的 CLIP（OpenAI训练的模型）、EVA-CLIP(腾讯训练的模型) 等预训练模型和语言侧的 OPT、FlanT5 等大语言模型（LLM）各自飞速进步，视觉-语言研究本应站在两者交汇处“收割”这些现成的单模态成果，但现有主流方法（如 Flamingo）普遍采用端到端预训练，将视觉编码器和语言模型全部放开、在数十亿图文对上从零一起训练，这带来了三重困境:

  1. 可训练参数动辄上百亿，训练成本随模型规模膨胀已高昂到令人却步
  2. 在图文数据上放开微调会大幅改写单模态模型的参数，引发灾难性遗忘，使其原有的视觉能力或语言推理、世界知识等本事明显退化
  3. 若为省算力而冻结这些模型，又会立刻暴露出模态鸿沟——LLM 在预训练中从未见过图像，根本无法理解视觉特征，而已有桥接方案仅依赖单一的生成损失，不足以实现精细的跨模态对齐。

2. 输入和输出分别是什么？

2.1 预训练

  分为两个阶段：表征学习和生成学习

注意下面关于本文使用 ViT 的输出是去掉原来的最后一层，并取倒数第二层 (因为原文说这带来了略微更好的性能)

关于 ViT 的设计参考：An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale

第一阶段：表征学习

输入： 图像 + 配对文本

step 1. 图像进入冻结 ViT

  • 输入 224 × 224 × 3 → 输出图像特征 257 × 1024 （ ViT-L ）

step 2. 32个可学习的 queries （ 32 × 768 ，是模型的参数）进入 Q-Former 图像分支

  • 与 step 1输出的图像特征做 交叉注意力 （ queries 是 Q ，图像特征是 K/V）
  • 输出查询表示 Z ：32 × 768 ——这是 Q-Former 对图像的”压缩摘要”

Step 3：配对文本进入 Q-Former 文本分支（BERT 分词）

  • 输出文本表示（如 [CLS] 的嵌入）

Step 4：用三个损失同时优化 Z 和文本表示

  • ITC：Z 与文本 [CLS] 算相似度，取最大 → 对比损失
  • ITG：用多模态因果掩码让文本分支从 Z 生成描述 → 语言建模损失
  • ITM：Z 与文本全互相看，二分类判断是否匹配 → 匹配损失

Step 5 阶段输出：训练好的 Q-Former（queries 学会提取”与语言最相关的视觉信息”）。此阶段没有任何用户可见的文本输出。

第二阶段： 生成学习 （加上冻结 LLM）

输入：图像 + 文本

Step 6：图像 → ViT → Q-Former → 得到 Z：32×768（同 Step 1–2）

Step 7：Z 经全连接层投影

  • 32×768 → 32×d_llm（OPT-2.7B: 2560 / OPT-6.7B: 4096 / FlanT5: 2048）
  • 输出 = 32 个”软视觉 token”（连续向量，不属于任何词表）

Step 8：文本用 LLM 自己的分词器编码（OPT 用 GPT-2 BPE，FlanT5 用 SentencePiece）

  • 输出文本 token 嵌入 N×d_llm

Step 9：把两者拼成 LLM 输入序列

  • OPT（decoder 型）：[32 个软视觉 token] + [文本嵌入] → 冻结 LLM 自回归生成文本 → 语言建模损失
  • FlanT5（encoder-decoder 型）：文本切成 prefix / suffix 两段
    • encoder 输入 = [32 个软视觉 token] + [prefix 嵌入] → 冻结 encoder
    • decoder 输入 = prefix，目标生成 suffix → 前缀语言建模损失

Step 10 阶段输出：完整 BLIP-2 模型。“输出”就是 LLM 逐 token 生成的内容（预训练阶段表现为损失，推理阶段表现为真实文本）。

2.2 推理阶段

输入：图像 + 自然语言指令

Step 1.：图像 → ViT → Q-Former → FC 投影 → 32 个软视觉 token（32×d_llm）

Step 2：指令文本用 LLM 分词器编码 → 嵌入 N×d_llm

  • OPT 提示模板：Question: {} Answer:
  • FlanT5 提示模板：Question: {} Short answer:

Step 3：直接把指令嵌入拼接在 32 个软视觉 token 后面

Step 4：冻结 LLM 自回归解码

  • beam search（width=5），length penalty = −1

Step 15 最终输出：跟随指令的文本

  • 可以是视觉对话、知识推理、故事创作等

  • 也可能出错：知识不准确、推理路径错误、信息过时

3. 整体流程是什么？各模块分别做什么？

  1. 冻结 ViT ： 把图像变为特征序列，输入 224×224×3 → 输出 257 个视觉 token（257×1024/1408）

  2. Q-Former：图像与语言之间的“翻译官 + 压缩器”，干三件事

    1. 抽取：32 个可学习 queries 通过 6 层交叉注意力，从 257 个视觉 token 中“主动采访”出与语言相关的信息
    2. 压缩：输出固定为 32×768——信息瓶颈，逼着只留关键信息
    3. 对齐：第一阶段用 ITC/ITG/ITM 三个损失，让抽取结果“面向语言”

    训练时不断修正参数。推理时参数冻结

  3. 全连接层 （ FC ）：最简单但不可或缺的“接口转换器”。把 32×768 投影成 32×d_llm（如 OPT 是 2560 维），使视觉向量落在 LLM 的词嵌入空间里，变成 LLM 读得懂的 32 个“软视觉 token”

  4. 冻结 LLM： 只管“说”，不管“看”。输入 = [32 个软视觉 token] + [文本/指令 token 嵌入] 。自回归逐 token 生成答案

关于核心 Q-Former :含有一个视觉提取的 Transformer 和一个文本 Transformer 。自注意力层（同一套权重，共享部分），

其中，关于自注意力层：

  • ITC 时：单模态掩码，Q-T不可见
  • ITG时：多模态因果掩码，queries 互看但不看文本；文本可看 queries 和之前的文本
  • ITM时： 双向掩码，Q-T完全互通

这三个按序逐步计算损失（注意方法不同），之后相加，最后向前传播并更新参数。

  关于这三种方法计算方式（损失函数），只在第一阶段时使用并更新 Q-Former 参数。在第二阶段时由于文本由 LLM 接管了，所以当冻结 ViT的输出进入 Q-Former 只进行图像分支并输出，在此阶段，由冻结的 LLM 返回梯度并更新参数（Q-Former 和 FC 层的参数）。

4. 与前一篇相比，核心变化是什么？

  上一个文章讲的是分割，这篇文章讲的是视觉与语言的一个联通问题。本文所使用的 Transformer 仅仅是 BERT的编码器，相比最初的加了规模、输入、预训练上的几处改进。

  并且本文不需要解码器，最初的解码器用于将编码器的输出转为对应的目标语言，而本文图像分支只做压缩（编码）；生成功能在阶段一由文本分支用因果掩码客串、在阶段二交给 LLM。而 BERT 与原版编码器的关系是“同一骨架、不同装备”——BLIP-2 选它，图的是现成的语言预训练权重和恰好契合三个损失的特殊 token 机制。

论文名称：Visual Instruction Tuning

阅读日期：2026.10.29

所属方向与编号：通用基础论文-06

预知识：

  1. LMM（Large Multimodal Model，大型多模态模型） ： 模型类别 ， 能够同时处理多种模态（如图像和文本）输入输出的大规模神经网络，是比 LLM 更广义的概念，Flamingo、BLIP-2、LLaVA 都属于此类
  1. 视觉指令微调（Visual Instruction Tuning）, 本文提出的训练范式 ， 作者首创的术语，指用”图像+语言指令”的多模态数据对 LMM 进行指令微调，以提升模型的视觉指令跟随能力
  2. 视觉提示微调（Visual Prompt Tuning）， 训练范式，它旨在提升模型适配的参数效率（只微调少量参数），而视觉指令微调旨在提升模型的指令跟随能力，两者目标完全不同
  1. 符号化表征（Symbolic Representations），数据编码手段 ， 因为 GPT-4 是纯文本模型”看”不了图，作者用两类文字符号代替像素输入 GPT-4：(i) Captions 描述视觉场景的多个视角；(ii) Bounding boxes 编码物体的类别和空间位置
  2. Caption（图像描述/字幕）， 符号表征类型 ， 人类标注的对图像内容的文字描述，本文使用 COCO 数据集每张图现成的 5 条描述
  3. Bounding Box（边界框），符号表征类型 ，用归一化坐标表示物体在图像中的位置范围，如 person: [0.681, 0.242, 0.774, 0.694]，每个框编码了”物体概念+空间位置”双重信息
  1. **LLaVA-Bench ** ，评测基准 ，测核心是让 GPT-4 充当裁判，而不是用传统的自动指标

测评流程如下：

  step 1. 构造评测三元组，每道评测题由三部分组成：图像 + 真值文本描述 + 问题。其中真值文本描述非常关键——COCO 版用的是 GPT-4 自动生成的详细描述，In-the-Wild 版则是人工撰写的极详细标注，如 Table 6 中拉面店、冰箱的例子长达数百词。

  step 2. 生成“参考答案”，让纯文本 GPT-4 阅读真值描述后回答问题。因为这个版本的 GPT-4 相当于“看到了完美图像理解的结果”，它的回答被视为该问题上的理论上限（满分参照）

  step 3. 候选模型作答 ，被测模型根据问题和真实图像，各自生成回答

  step 4. GPT-4 裁判对比打分，裁判 GPT-4 收到的是：问题 + 真值文本描述（代替图像）+ 被测模型的回答 + 参考模型的回答，然后从四个维度评估：Helpfulness（有用性）——回答是否真正帮到了用户；Relevance（相关性）——是否切题、是否跟随了指令；Accuracy（准确性）——结合真值描述判断内容是否正确；Level of detail（详细程度）——信息量是否充分。最后给出 1-10 的综合分，并要求裁判附上评语解释。

  Step 5. 计算相对得分，被测模型得分 ÷ 参考答案得分 = 相对得分（以“能看到真值描述的 GPT-4”为 100% 基准）

1. 这篇论文要解决什么问题？

  如何构建一个能像 ChatGPT 理解文本指令一样理解“视觉+语言”混合指令的通用多模态助手，而其中的关键瓶颈在于视觉-语言指令跟随数据的严重缺失。

背景介绍

  2022 年底 ChatGPT 与 2023 年 GPT-4 相继问世，NLP 领域的指令微调（Instruction Tuning）范式被证明威力巨大——用机器生成的“指令-回答”数据微调大语言模型（LLM），就能让模型听懂自然语言指令、灵活切换任务，开源社区也随之涌现出 LLaMA、Vicuna 等强模型。但这场“指令革命”完全局限于纯文本世界。
  与此同时，计算机视觉领域仍是“一个任务一个专用模型”的格局：语言仅用于描述图像内容，模型接口固定、交互性差；Flamingo、BLIP-2、OpenFlamingo 等虽能处理图像输入，却从未用视觉-语言指令数据微调过，多模态表现明显落后于纯语言任务。
  将指令微调推广到多模态领域的最大障碍是数据的缺失——人工标注“图+指令+回答”格式的数据耗时且规范难定，而海量现成图文对又缺乏指令多样性与推理深度；且当时公开的 GPT-4 并不接受图像输入。
  在此背景下，本文首次提出视觉指令微调（Visual Instruction Tuning）：利用纯文本 GPT-4 作“教师”，借助 caption 与 bounding box 两类符号化表征，将现成图文对自动转化为 158K 多模态指令数据，进而训练出端到端的开源多模态模型 LLaVA（CLIP 视觉编码器 + 线性投影 + Vicuna），并建立首个多模态指令跟随评测基准 LLaVA-Bench，为构建通用视觉助手迈出关键一步。

2. 输入和输出分别是什么？

2.1 训练阶段

stage 1. 特征对齐预训练

  输入： 图像+简短描述指令

  • Step 1：图像 $X_v$ 进 CLIP 编码 → $Z_v$ → 投影得 $H_v$
  • Step 2：随机采样的描述指令（如 “Describe the image concisely”）编码为文本 token
  • Step 3：拼接 [指令, 视觉 token]（或 [视觉 token, 指令]，随机选择）送入 LLM
  • Step 4：模型预测目标 = 原始 caption，按式 $p(X_a|X_v, X_{instruct}) = ∏ p_θ(x_i | X_v, X_{instruct},<i, X_a,<i)$ 计算自回归损失

  输出：原始 caption

这个阶段可以理解为为冻结的 LLM 训练一个兼容的视觉分词器。

Stage 2：端到端指令微调

  输入：论文自建的 LLaVA-Instruct-158K（GPT-4 生成的 158K 多模态指令数据）。此时的输入序列是标准的多轮对话格式：

$$
\begin{aligned}
&X_{\text{system-message}} \\
&\text{Human: } X^1_{\text{instruct}} \quad \text{Assistant: } X^1_a \\
&\text{Human: } X^2_{\text{instruct}} \quad \text{Assistant: } X^2_a \cdots
\end{aligned}
\tag{1}
$$
其中每轮的指令按下式：
$$
\mathbf{X}^t_{\text{instruct}} =
\begin{cases}
\text{Randomly choose } [\mathbf{X}^1_{\mathbf{q}}, \mathbf{X}_{\mathbf{v}}] \text{ or } [\mathbf{X}_{\mathbf{v}}, \mathbf{X}^1_{\mathbf{q}}], & \text{the first turn } t = 1 \\
\mathbf{X}^t_{\mathbf{q}}, & \text{the remaining turns } t > 1
\end{cases}
\tag{2}
$$

即 第一轮指令 = 问题与图像 token 的随机拼接顺序，后续轮次只有问题文本

  Step 1： 图像 $X_v$ → CLIP（冻结）→ $Z_v$ → 投影 W → $H_v$；
   Step 2： 系统消息 + 第一轮（问题 + 视觉 token，顺序随机）+ 助手回答 + 后续多轮问答，按 Table 2 格式拼成完整序列；
  Step 3：模型自回归前向计算；
  Step 4： 损失只计算“预测 token”——即助手回答部分（包括停止符）：

即：

  • 输入 = 图像 + 158K 多轮对话指令序列
  • 预测目标 = 助手回答 token（含 STOP）
  • 可训练参数 = 投影矩阵 W + LLM 全部参数 ϕ
  • 视觉编码器始终冻结

Stage 2 的 ScienceQA 变体：输入格式退化为单轮对话

即：

  1. 输入 = 问题 + 上下文（自然语言或图像）

  2. 预测目标 = 先推理过程后答案 (reasoning-first）

2.2 推理阶段

场景 1：多模态 Chatbot

 Step 1： 用户上传图像 $X_v$ + 输入自然语言问题（如 “What is unusual about this image?”）
 Step 2： 图像走 CLIP → 投影 → 视觉 token $H_v$，与问题 token 拼接
 Step 3：LLM 自回归生成回答 $X_a$，直到模型自己预测出 STOP 符号###停止
 Step 4（多轮）：用户继续追问（如 “I would like to do the fruit salad. Show me the recipe.”），此时图像不再重复输入，模型基于第一轮的视觉 token + 对话历史继续生成——对应式 (2) 中 $t > 1$ 轮只有文本的设计；用户也可要求清空历史重新开始。


场景 2：ScienceQA 推理

 Step 1：输入 = 题目问题 + 上下文（自然语言或图像；无图像时只有文本）；
 Step 2：模型采用 reasoning-first 策略生成，即输出 = 讲义/推理过程 + 最终选项；
 Step 3（可选的 GPT-4 集成）：当 LLaVA 与文本 GPT-4 答案不一致时，将问题 + 两个模型的回答文本再次喂给 GPT-4 作判官，输出最终裁决答案—— 此时 LLaVA 的输出（推理+答案文本）成了 GPT-4 判官的输入之一。

3. 整体流程是什么？各模块分别做什么？

  Step 1. 图像 → 视觉特征 $Z_v$ : 输入图像 $X_v$ 首先经过预训练的 CLIP 视觉编码器 ViT-L/14 提取特征，本文采用的是倒数第二层的特征（已经做实验与最后一层比较）

  Step 2. 视觉特征 $Z_v$ → 视觉词元 $H_v$ : 视觉特征经过可训练的线性投影矩阵 W，被映射到与 LLM 词嵌入空间同维度的向量序列。然后，图像变成了一串“视觉 token”（$H_v$），形式上与文字 token 完全平等，可以直接和文字拼接。

  Step 3. 语言指令 $X_q$ → 文本词元 $H_q$ : 用户问题 $X_q$ 经过 LLM 原生的 embedding 层得到 $H_q$，然后视觉词元 $H_v$ 与文本词元 $H_q$ 拼接成一个统一序列，一起送入语言模型 $f_ϕ(·)$。按式 (2)，第一轮指令中问题与视觉 token 的顺序是随机选择的（[X_q, X_v] 或 [X_v, X_q]），后续轮次只有问题文本，图像只在第一轮输入一次

  Step 4. 统一序列 → 自回归生成回答 $X_a$ ，语言模型对拼接后的序列做自回归解码，逐 token 生成回答：$p(X_a|X_v, X_{instruct}) = ∏ p_θ(x_i | X_v, X_{instruct},<i, X_a,<i)$

  对于式$p(X_a|X_v, X_{instruct}) = ∏ p_θ(x_i | X_v, X_{instruct},<i, X_a,<i)$ 中的条件，本文显式地添加了 $\mathbf{X}_{\text{v}}$，以强调图像对所有答案的接地（grounded）作用；同时为了更好的可读性，本文省略了 $\mathbf{X}_{\text{system-message}}$ 以及所有之前的 <STOP>。对于 LLaVA 模型的训练，本文采用了双阶段的指令微调流程。

  其中 $\boldsymbol{\theta}$ 是可训练的参数，$\mathbf{X}_{\text{instruct}, <i}$ 和 $\mathbf{X}_{\text{a}, <i}$ 分别是所有轮次中、当前预测 token $\boldsymbol{x}_i$ 之前的指令和答案 token。预测 token 的见 公式（1）。

4. 与前一篇相比，核心变化是什么？

  前一篇的 BLIP-2 同样也是根据图片产生信息，不过 BLIP-2 更偏重于以很少的代价将图片送入 LLM ，他通过设计了一个 Q-Former 连接了 ViT 和 LLM，实现了以很少的代价实现了视觉-语言的对话。

  本文则重点教会了模型听懂人的指令。在训练阶段已经进入了微调的行为，前者则仍是偏重训练出对应的模型参数。并且本文已经支持了多轮对话，前者则只是一图一答的行为。并且本文也提出了视觉指令微调的概念，让模型像ChatGPT一样工作（另需注意，当时背景下，CPT并不支持图片的输入，仅仅是文本对话）。
